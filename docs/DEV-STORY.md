作为一名坚持力量训练多年的撸铁党，我一直有个痛点：**市面上的健身记录 App 都不顺手**。

- 有的要注册登录，隐私堪忧

## 一、为什么选 PWA？

第一版考虑过写原生 App，但很快否掉了：

| 方案 | 缺点 |
|------|------|
| iOS 原生 App | 需要 Mac + 开发者账号（$99/年）+ 上架审核，成本高周期长 |
| Android 原生 App | 需要 Java/Kotlin 开发，还要适配各厂商应用商店 |
| 小程序 | 受平台规则约束，功能受限，还得过审 |
| **PWA（渐进式 Web 应用）** | **零成本、跨平台、可离线、可装桌面，一次开发处处运行** ✅ |

PWA 的杀手锏是 **Service Worker**：首次访问时把全部资源缓存到本地，之后**断网也能打开**；配合 manifest 配置，还能像原生 App 一样**添加到手机桌面**、全屏运行。这完全命中我的需求。

技术栈也刻意保持简单：**纯 HTML + CSS + Vanilla JavaScript，零框架零依赖**。不是不会用框架，而是这种工具型应用用原生反而更快更轻 —— 全部代码才 200 多 KB，打开即用。

## 二、功能设计：以撸铁党的习惯为核心

产品设计上没有堆功能，而是聚焦训练中最常用的交互：

### 🏋️ 1. 训练计划管理
- 支持创建多个训练计划（推/拉/腿循环、上肢综合等），动作自由编排
- 首页只保留一个「+ 新建计划」入口，避免误触，界面干净

### 📋 2. 动作库（内置 22 类动作）
- 每个动作配 **AI 生成的肌肉解剖图**，一眼看清目标肌群
- 左侧**解剖部位导航**（胸/背/肩/腿/核心…），右侧**器械筛选**（杠铃/哑铃/器械/自重…）
- **支持自定义创建动作**：拍照/选图、命名、选部位、选器械，一键入库，图片自动压缩存储

### ⏱️ 3. 训练进行页
- **每个动作独立设置组间休息**：内置倒计时器，训练完一组自动开始倒计时，可拖动调节时长
- **训练备注**：随时记录组数、重量、次数、动作感受
- **超级组**：两个动作连做共享休息，提升训练效率
- **自由删组**：左滑组行即可「向下复制 / 标记热身组 / 删除」，操作符合直觉
- **滚轮选择器**：重量（KG/LB 可切换）和次数用 iOS 风格滚轮快速输入，比键盘快 3 倍

### ⚙️ 4. 动作级菜单
替换动作 · 删除动作 · 动作排序 · 计时设置 · 记录想法 · 修改为 LB · 设为超级组 —— 全部可用

### 📴 5. 完全离线（PWA）
- Service Worker 预缓存全部资源与图片，首次加载后断网可用
- 安装到桌面后全屏运行，无浏览器地址栏，体验等同原生

### 📊 6. 数据统计
训练历史、次数/重量趋势可视化，帮你复盘每一次进步

## 三、架构设计：一份核心 + 增强包的巧妙结构

项目采用了一个很有意思的架构 —— **「核心 + 增强包」双文件模式**：

```
fitrecord/
├── app.js          # 核心逻辑（v3 基础版）
├── exercises.js    # 动作库数据
├── enhance.js      # 增强包（v4 新功能，后加载覆盖）
├── enhance.css     # 增强样式
├── sw.js           # Service Worker（离线缓存）
└── img/            # AI 生成的 22 张动作解剖图
```

核心思路：**enhance.js 在 app.js 之后加载，用同名函数覆盖实现新功能**，互不侵入、可插拔。比如原来的 `renderHome()` 在新版中完全重写，而基础数据层不受影响。这种模式的好处是：升级功能时不用动老代码，出问题可以秒回滚。

有几个技术点值得一提：

### 1. 避免递归的赋值式覆盖

JavaScript 的函数声明有提升特性，直接重写同名函数会导致新旧函数互相引用、无限递归。正确做法是**赋值式包装**：

```js
const _openWorkoutBase = openWorkout;
openWorkout = function() {
  _openWorkoutBase.call(this);  // 先执行原逻辑
  // 再叠加新逻辑：设置头图背景、初始化计时器等
};
```

### 2. 组行左滑交互

用 `touchstart / touchmove / touchend` 实现原生左滑，配合 `transform: translateX` 平移，露出底部的「向下复制 / 热身组 / 删除」三个操作按钮。关键是要处理点击穿透：滑动结束后短时间内屏蔽 click 事件，避免误触。

### 3. 滚轮选择器

不用第三方组件，直接用 **CSS scroll-snap** 实现 iOS 风格滚轮：一个可滚动列表 + `scroll-snap-align: center` 吸附居中，配合高亮中间项。重量按 2.5kg 步进（最大 200kg），次数 1-100，支持 KG/LB 单位切换。

### 4. 图片压缩存储

自定义动作的图片用 canvas 压缩到 480px 宽的 JPEG（质量 0.8）再转 base64 存 localStorage，单张图片仅几 KB，不撑爆存储空间。

## 四、离线方案：Service Worker 缓存策略

离线是 PWA 的灵魂，我的策略是 **stale-while-revalidate（边用边更新）**：

```js
self.addEventListener('fetch', (e) => {
  if (e.request.method !== 'GET') return;
  e.respondWith(
    caches.match(e.request).then((cached) => {
      const fetchPromise = fetch(e.request).then((res) => {
        if (res && res.status === 200 && res.type === 'basic') {
          const copy = res.clone();
          caches.open(CACHE).then((c) => c.put(e.request, copy));
        }
        return res;
      }).catch(() => cached);
      return cached || fetchPromise;
    })
  );
});
```

- **有网**：先返回缓存（秒开），后台静默更新缓存，下次访问就是新版
- **断网**：直接命中缓存，App 完整可用
- 缓存版本号管理（`CACHE = 'fitrecord-v4'`），升级时自动清理旧缓存

## 五、AI 生图：22 张肌肉解剖图的生产流水线

动作库的配图是另一大工程 —— **22 张肌肉解剖示意图全部由 AI 生成**。

过程中踩了不少坑，分享几个关键经验：

1. **提示词要带"着装"**：裸肌解剖图容易被内容审核误判，加上 `wearing dark gym clothes / tank top` 即可通过
2. **文件名冲突**：并行生成时 AI 工具会用提示词前几个词做文件名，容易互相覆盖 —— 让每张图的提示词开头都有独特标识词
3. **尺寸与体积**：统一生成 512px，压缩到 15-24KB/张，22 张总共才约 470KB，完全不影响加载速度

## 六、踩坑实录：那些值得记录的 Bug

### 🕳️ 坑 1：函数提升导致的无限递归
重写同名函数时，由于 JS 函数声明提升，新函数捕获到了它自己 → 无限递归崩溃。解决方案就是前面说的**赋值式包装**。

### 🕳️ 坑 2：iOS 刘海屏把标题盖住
`viewport-fit=cover` + `black-translucent` 状态栏会让页面内容延伸到刘海区域。修复：给所有顶部容器加安全区域适配：

```css
.home-header {
  padding-top: calc(8px + env(safe-area-inset-top, 0px));
}
```

### 🕳️ 坑 3：PWA 装完后不更新
Service Worker 缓存了旧版，用户装了桌面图标后刷新看不到新功能。后来统一用缓存版本号 + 重新安装解决。
